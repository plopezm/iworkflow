# go-migration

Goal: migrate iworkflow from Rust (Leptos + Diesel) to Go (templ + htmx + Tailwind, chi, sqlc, goose, modernc sqlite), keeping all features. Rust and Go coexist on branch `feat/golang` until parity; no big-bang. Conventions live in `AGENTS.go.md`.
Workers: read this file down to `## Log`, follow `AGENTS.go.md`, and report which `S#` they covered. Cargo/go commands with `-j 2` / `-p 2`, long ones in background.

## Specs

- S1: "Quiero migrar el proyecto a golang, manteniendo las funcionalidades." Every existing feature keeps its observable behavior.
- S2: "Lo primero sería generar el AGENTS.md correspondiente al que hay pero en golang." `AGENTS.go.md` exists and follows the structure of `AGENTS.md`.
- S3: UI stack decision by user: "templ + htmx + Tailwind (SSR)". Libraries approved by user: `chi`, `sqlc`, `goose`, `modernc.org/sqlite` ("me gusta todo, adelante").
- S4: Parity criterion: a migrated module is done only when its current e2e (`end2end/<module>.e2e.cjs`) passes against the Go version and its Rust tests have Go counterparts (`AGENTS.go.md` §5).
- S5: Existing migrations (`migrations/`, 24) are ported unchanged in effect: the Go DB schema equals the Rust one, and `goose redo` works.
- S6: `tasks` slice order A → B → D → C → E → G → F → H (A task-core, B events/SSE, D attachments/files, C graph, E worktree/git, G usage-limit resume loop, F agent runtime/PTY, H presentation).
- S7 (high risk, independent verification + own commit): data/migrations (S5), agent process/PTY lifecycle (kill semantics, orphans), optimistic start claims `claim_for_start`/`revert_start_claim`, SQLite busy retries, git `sweep_orphans`, credentials in jira/code_hosting.
- S8: Layering rules of `AGENTS.go.md` §3.1 are enforced by lint (`depguard`/`go-arch-lint`).
- S10 (worker contract): workers edit only their Allowed edit surfaces; never `go.mod`/`go.sum` (dependencies are pre-added; report any missing one), never `internal/app/app.go` (the parent wires `<Feature>Module` after the worker reports), no global `make generate`: run `templ generate -path <own dir>` and `sqlc generate` inside the module's persistence folder (each module owns `sqlc.yaml` there, schema = `internal/core/db/migrations`). Use `go test -p 2` and `golangci-lint run ./<own pkgs>/...`. Persistence tests use `dbtest.New(t)`. Presentation (templ) waits for T1g unless the worker only needs `components.Card/Badge/ErrorText`.
- S11: Quality debt D1-D11 is mandatory (user: "quiero asegurar la calidad por lo que tenemos que hacerlo").
- S9: Commits in reviewable units of ~400 authored lines on `feat/golang`; push, PR and merge are the user's decisions. Rust code is removed only at the end and `AGENTS.go.md` replaces `AGENTS.md` then.
